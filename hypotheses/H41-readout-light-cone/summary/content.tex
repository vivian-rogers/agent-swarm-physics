\hwhat{Can a novel item (a link, number, name or rare word) reach an agent before that agent's model calls could have read it? We traced 134k novel marker items (H34's rule; 45k adoptions) through the DQ1 context ledger in 32 non-holdout periods, building each item's logged light cone: the time-respecting read-out paths from its first use. Within a room the bound holds: adoptions outside the cone are rare (robust share 0--4\% per period, median 0.6\%). The pre-registered test of gating, the hazard at the first call that read the item over the call already in flight, passed in only 12/32 periods. Matched for time since the item appeared (post hoc), it passes in 22/32. Across rooms the logged cone is a cage: 75--100\% of cross-room adoptions lie outside it (7/8 two-room periods), and NE42's merge raised the cross-group hazard 80--860$\times$, falling back at the split. The front is paced by talk turns, not cadence. Holdout untouched.}

\hmodel{Asynchronous kinetic updates (model 02) with contagion on a temporal graph (03). Agents update only at their model calls; a call reads the room messages posted since the previous call (the ledger). An item posted by source $s$ at $t_0$ can reach agent $i$ only along a time-respecting read-out path; $K_i$ is $i$'s entry call into this logged cone. Adoption hazard per talk call: a shared field $\varepsilon$, unlogged channels $\eta$, plus $q$ once $i$ has read the item. $J$ compares the hazard at the first entry call with the call in flight at $t_0$.}

\hmath{\vspace{-5pt}\begin{gather*}
T_s=t_0,\quad T_i=\min\{t^{\rm call}_c:\ c\ \text{reads}\ m,\ t_m\ge T_{{\rm src}(m)}\}\\
\lambda_i(c)=\varepsilon(t_c)+\eta_i(c)+q\,\mathbb{1}[c\ge K_i^{\rm item}]\\
\text{acausal: } c_{\rm use}<K_i,\qquad J=\frac{h(c=K_i)}{h(c=K_i-1)}\Big|_{\text{same }t-t_0}\\
v=1/\mathrm{median}\,(\text{calls from exposure to use})
\end{gather*}\vspace{-7pt}}

\htelos{For an operator the useful part is negative: you cannot trace how cross-room information leaked from chat logs. Nearly all cross-room adoptions bypass the logged chat channel, yet shared repos and websites are as common among in-cone adoptions as among the leaks, so they explain nothing. Only humans re-posting an item in several rooms stand out (27$\times$ enriched). Rooms work as cages for chat: merging two groups multiplies cross-group pickup about a hundredfold. Inside a room, gating is real but weak: about a third of fast adoptions are co-generated (a shared field), not read. Spread runs at one hop per 1.5--5 talk turns, so tuning call cadence buys nothing.}

\hbottom{Novel items obey a logged light cone inside rooms and across the NE42 merge and split, but the pre-registered gating test mostly failed (it passes only after a post-hoc recency match), and cross-room leaks cannot be traced to any logged channel.}

\hcaveats{The headline gating result rests on a post-hoc estimator, chosen after the first real period and validated afterwards (8\% false positives under a field). Items are hashed markers, so co-generated names and numbers look like adoptions. Channel attribution is non-specific because shared work is ubiquitous. Visibility is the ledger's room rule; its timing is estimated for non-Gemini agents. The cadence test lacks leverage: regime-III call intervals barely vary. NE42 is confounded with \#40's shared goal. The first build mis-stored cone hop counts (fixed; all periods rebuilt). No multiplicity correction across 32 periods. Holdout not run.}
