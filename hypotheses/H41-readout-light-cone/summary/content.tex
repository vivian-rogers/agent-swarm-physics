\hwhat{H41 asks whether a novel item (a link, number, name or rare word) can reach an agent before that agent's model calls could read it. The test traces 134k novel marker items (H34's rule; 45k adoptions) through the DQ1 context ledger in 32 non-holdout periods. Each item gets a logged light cone: the time-respecting read-out paths from its first use. Within a room the bound holds. Adoptions outside the cone are rare: the share $A_{\rm rob}$ is 0--4\% per period, median 0.6\%. The pre-registered gating test compares the hazard at the first call that read the item with the call already in flight. It passes in only 10--12/32 periods (the range is bootstrap jitter). Matched for time since the item appeared (post hoc), it passes in 22--24/32. Across rooms the logged cone is a cage: 75--100\% of cross-room adoptions lie outside it (7/8 two-room periods). The NE42 merge raises the cross-group hazard 80--860$\times$, and it falls back at the split. Rooms that agents hop between (\#51) leak: 47\% of cross-room adoptions lie outside the cone. Talk turns, not cadence, pace the front. The holdout is untouched.}

\hmodel{Model 02 gives asynchronous kinetic updates, and model 03 gives contagion on a temporal graph. Agents update only at their model calls. A call reads the room messages posted since the previous call (the ledger). An item that source $s$ posts at $t_0$ can reach agent $i$ only along a time-respecting read-out path. $K_i$ is $i$'s entry call into this logged cone. The adoption hazard per talk call is a shared field $\varepsilon$, plus unlogged channels $\eta$, plus $q$ once $i$ has read the item. $J$ compares the hazard at the first entry call with the call in flight at $t_0$.}

\hmath{\vspace{-5pt}\begin{gather*}
T_s=t_0,\quad T_i=\min\{t^{\rm call}_c:\ c\ \text{reads}\ m,\ t_m\ge T_{{\rm src}(m)}\}\\
\lambda_i(c)=\varepsilon(t_c)+\eta_i(c)+q\,\mathbb{1}[c\ge K_i^{\rm item}]\\
\text{acausal: } c_{\rm use}<K_i,\qquad J=\frac{h(c=K_i)}{h(c=K_i-1)}\Big|_{\text{same }t-t_0}\\
v=1/\mathrm{median}\,(\text{calls from exposure to use})
\end{gather*}\vspace{-7pt}}

\htelos{Do not try to trace cross-room leaks from chat logs. Nearly all cross-room adoptions bypass the logged chat channel. Shared repos and websites are as common among in-cone adoptions as among the leaks, so they explain nothing. Only humans who re-post an item in several rooms stand out (27$\times$ enriched). For chat, fixed rooms work as cages: a merge of two groups multiplies cross-group pickup about a hundredfold. Rooms that agents hop between leak about half the time. Inside a room, gating is real but weak: about a third of fast adoptions are co-generated by a shared field, not read. Spread runs at one hop per 1.5--5 talk turns, so a change in call cadence buys nothing.}

\hbottom{Novel items obey a logged light cone in rooms and across NE42; the pre-registered gating test passes only post hoc, and no logged channel explains cross-room leaks.}

\hcaveats{The headline gating result rests on a post-hoc estimator. It was chosen after the first real period and validated afterwards (8\% false positives under a field). Items are hashed markers, so co-generated names and numbers look like adoptions. Channel attribution is non-specific because shared work is everywhere. Visibility follows the ledger's room rule, and its timing is estimated for non-Gemini agents. The cadence test lacks leverage: regime-III call intervals barely vary. \#40's shared goal confounds NE42. The first build mis-stored cone hop counts; the fix rebuilt all periods. Round 1b fixed the room index (open room segments were dropped). It changed \#51 (63\% of lookups) and slightly \#33 and \#44: \#51's jump fell from 41 to 2.1 (matched 16 to 9.2), and its bridging result reversed. The analysis has no multiplicity correction across 32 periods. The holdout is not run.}
