## Why it is not tested
In Kolchinsky–Wolpert terms NE14 changes the *erasure schedule* of the context window (a dynamic intervention on how often C is wiped and re-encoded into memory). H09 measured the change: memory snapshots per hour 15.9 → 5.1, per-snapshot turnover 0.23 → 0.38 (13 agents present on both sides). But NE14 is bundled with the consolidate tool, the pause tool and perma-computer-use (the regime II → III boundary), and the pre side is partly in the NE30 holdout window. Any ΔV across it can't be attributed to the erasure rate, so H15 makes **no prediction** and runs no test here.

The within-regime-III version of the same question, which *is* identified, is the forced-vs-voluntary consolidation contrast (card P5, `G36b` … `G51`): forced consolidations wipe the context at a fixed turn count regardless of task state.
