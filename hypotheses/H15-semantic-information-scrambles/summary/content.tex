\hwhat{Natural scrambles in non-holdout data, per goal period, against a placebo-day null (a synthetic check on the real village skeleton: calibrated, power 17--41\%). \textbf{Memory:} 12 losses of 50--80\% of an agent's memory and 20 newcomers with empty memories showed no day-scale cost on viability $V^*$: memory loss $-0.55$ SD [$-1.78$, $+0.68$] (2 periods), newcomers $+0.15$ [$-0.18$, $+0.47$] (\emph{more} engaged early); the rewrite control was null. \textbf{Chat cuts:} only 3 usable events. \textbf{Context:} consolidations wipe the context window (forced every 41 turns) but keep memory. The pre-registered forced-vs-voluntary contrast came out wrong-signed (task-phase confound). Post hoc, writes drop 33--53\% for $\sim$10 turns after a forced wipe in 8/9 regime III periods, however much was saved to memory. D2.6 found no homeostatic $V$. \textbf{Round 1b} (work ledger, real failures, context ledger): the nulls stand and a forced wipe costs $-39\%$ work commits for ten calls ($\approx$10\% of output). Holdout not run.}

Scrambles erase $M$ or $C$, or cut $Y\to X$; $\hat p$ = the scrambled joint. $V$ = viability per agent-day (5 candidates) or per turn (writes); $u$ = its same-day residual; $\delta$ = fraction removed; $S$, $\eta$ = semantic information, its share of $I(X;Y)$.}

\htelos{Mostly confirms what people running LLM agents already suspect: the working context keeps an agent productive, and a long-term memory file is something it rebuilds from its environment within a day. The one usable number is the cost of a context reset, about 45\% of writes for $\sim$10 turns (about a tenth of output at a 41-turn cadence). The levers are a longer cap or a task-state summary carried across the reset; today's memory write doesn't recover the loss. That is scaffold engineering, not physics, and post-hoc until the holdout check (C3) runs. Kolchinsky--Wolpert adds vocabulary (stored vs.\ observed information) but here measured neither $S$ nor $\eta$, nor a viability function.}
\hbottom{Day-scale memory (and the repo an agent works in) carries no detectable load-bearing information; the context window does: a forced wipe costs $-39\%$ of committed work for ten calls, about a tenth of output, whatever the agent saves to memory (round 1b; holdout pending).}
