\hwhat{H42 redoes H03's multivariate Hawkes fits with kernels anchored at the recipient's next model call, the read-out call from the context ledger. The fits cover 71 non-holdout period units in 35 periods, with synthetic validation, shift and day-block nulls, and four native tests. A read-out kernel does not raise cross-excitation; it removes most of it. Talk locks to each agent's \emph{own} call clock. A model in which talk can only follow the recipient's call starts wins by 1.1 nats per held-out message in 57/57 units. Inside that model, messages read at a call barely change whether the agent talks: $n_{\rm cross}\approx 0.004$, against 0.061 for H03's exponential kernel. Regime I is $\approx 0$; regime III is 0.01--0.05. The pre-registered estimator ``confirms'' the prediction but fails the synthetic guard. Natives NE41, NE14 and \#51 fail. Post hoc, messages that \emph{name} the recipient carry 0.15 extra talk events each in regime III. The holdout is not run.}

\hmodel{Model 09 (multivariate Hawkes) in two worlds: $\lambda^A$ is the H03 world and $\lambda^B$ the call-clock world. Events are agent chat messages. Sources are other agents' messages that agent $i$ read (ledger pairs). $c_k$ is the start of $i$'s $k$-th call, and $k^*$ the latest. $f_i$ is the talk-delay density, and $\kappa$ the call class (chat or computer use, wake or not). $k_1(m)$ is the call that read message $m$. $w_b$ are read-out weights over call-index bins $b$; $\alpha_q,\beta_q$ form an exponential grid. $X_i$ is the cross part, and $n_{\rm cross}$ the cross offspring per event.}

\hmath{\vspace{-5pt}\begin{gather*}
\lambda^{A}_i=c_{id}s_{b}+\Phi^{\rm self}_i+\textstyle\sum_{m}\sum_q\alpha_q\beta_q e^{-\beta_q(t-s_m)}\\
\lambda^{B}_i=f_i\big(t-c_{k^*}\big)\Big[c_{id\kappa}s_b+\Phi^{\rm self}_i+\textstyle\sum_b \frac{w_b}{M_b}N_b(k^*)\Big]\\
N_b(k^*)=\#\{m:\,k^*-k_1(m)\in b\},\quad k_1(m)=\min\{k:\,c_k>s_m\}\\
n_{\rm cross}=\textstyle\frac{1}{N}\sum_i\int X_i(t)\,dt
\end{gather*}\vspace{-7pt}}

\htelos{Before you fit an influence model to agent logs, model each agent's call schedule and call class. Event-timing ``contagion'' between LLM agents mostly follows each agent's own call clock. Without the call clock, branching ratios and influence graphs from timestamps mostly measure the scaffold, and shift nulls do not catch this. With it, an ordinary message barely changes whether an agent speaks. The one handle left is direct address. In the always-on regime, a message that names an agent adds about 0.15 talk events at its next call (post hoc; mid-exchange confound open). To get a response, name the agent, as H29 also finds. The read-out kernel itself is not a new knob.}

\hbottom{A read-out-anchored kernel reveals no hidden coupling: each agent's own call clock sets talk timing, and real message-driven excitation is confined to messages that name the recipient.}

\hcaveats{The call-clock world takes call times and call classes as given. It therefore excludes by construction any influence that changes \emph{when} or \emph{how} an agent calls; the activity channel is only a partial check. Outside Gemini, call starts are calibrated, not measured (regime-I chat calls are latency-placed); bound sensitivity changes nothing. Shift and day-block nulls do not control a shared 15-min field. The card has three dated amendments (two estimator worlds, the field floor); it reports the pre-registered verdicts and voids them. The named-message result is post hoc, and recipients mid-exchange are its main rival.}
