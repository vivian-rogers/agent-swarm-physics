\hwhat{The test builds the Kolchinsky--Wolpert channel table: for each information channel, the allocation bits it carries ($I_c$) and the commits lost when it is naturally scrambled ($\Delta V_c$). The ratio $\kappa_c$ is commits per 20 calls per bit. The main design pools 18{,}760 non-holdout forced erasures against matched pseudo-erasures. Only the context window has value: $\kappa_C=5.2$ [3.8, 7.9]. Its erasure costs 41\% of output for 0.08 bits. The own artifact carries the most bits (0.14) but no value: $\kappa_A=-0.6$ [$-1.6$, $+0.3$]. Memory, chat, search and human messages carry $\le0.04$ bits each, with value consistent with 0. The kickoff carries 0.36 bits and costs nothing. The predicted order (artifact first) fails. Receiving chat after an erasure raises output 22\% without allocation bits. The holdout script exists and is not run.}

\hmodel{Semantic information, natural-scramble variant (model 04); plug-in estimators (model 12). The system $X^+$ is an agent's next allocation: the repo of its first work commit in 20 calls. Each channel $c$ has a pointer $S_c$, the repo it names. It is open ($o_c$) when it names the agent's own artifact. The scramble $s$ is a forced erasure. A pseudo-erasure at call 21 of a long segment is the placebo. $V$ counts work commits in 20 calls; the Poisson fit also adjusts for $\log(1{+}V_{\rm pre})$, commits in the 20 calls before. Strata $g$ are agent $\times$ period. For the context row, $I_C=I_{s=0}-I_{s=1}$ and $\Delta V_C$ is the erasure cost; $\kappa$ is defined only where the CI of $I_c$ lies above 0.02 bits.}

\hmath{\vspace{-6pt}\begin{gather*}
I_c=\hat I_{\rm MM}(X^+;S_c)\big|_{s=1}-\big\langle \hat I_{\rm MM}(X^+;S_c^{\pi})\big\rangle_{\pi\in g},\qquad \kappa_c=\Delta V_c/I_c\\
\log E[V]=\phi_{g,s}+b_1 o_c+b_2\,o_c s+\dots,\quad \Delta V_c=\bar V_{o,s}(1-e^{-b_2})
\end{gather*}\vspace{-8pt}}

\htelos{Protect the context window, not the notes. A forced erasure costs 41\% of the next 20 calls' commits, 5.2 commits per 20 calls per bit removed. Lengthening the 41-call cap is the lever with a measured payoff. Do not expect memory notes, larger memories, history search or repo-naming chat to buy it back: none shows value above 0. The own repo is the best pointer (0.14 bits; return 0.96 when re-read), but re-reading after an erasure gains nothing beyond what it gains at any call. Chat after an erasure does raise output (+22\%), so a short status message to a freshly erased agent is a cheap candidate lever. It is untested as an intervention.}

\hbottom{Of seven information channels, only the context window buys commits per bit ($\kappa_C=5.2$); the artifact carries more bits but no measurable value.}

\hcaveats{$\kappa$ is a ratio of two noisy numbers. It is defined for context and artifact pooled, and for context alone in only 2/9 periods. Allocation is coarse-grained to the repo, so chat and human messages score near 0 bits by construction. Open flags are chosen by the agent. Search (46 open erasures) and human rows are unpowered. The chat row reproduces H70's room row. The per-period rule was clarified after the run; both counts are reported. $\eta=S/I$ is not identified: natural scrambles give one point, not the information--viability curve.}
