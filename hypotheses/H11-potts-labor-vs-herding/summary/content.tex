\hwhat{Rounds 1 and 1b fitted a Curie--Weiss Potts model per week. The spin is an agent's project in a 30-min window. The goal-mode rule for the sign of $\beta J$ failed: agents herd ($\beta J>0$) in 11/14 weeks, in attention and in work commits, and spread only when the task gives each agent its own artifact. \textbf{Round 2 asks why agents pile on.} The degrees of freedom are \emph{joins}: an agent switches to a project that others already hold. We fit the choice among all live projects with a conditional logit. Its attachment exponent $\alpha$ says how the odds grow with others' recent activity. Lead placebos test the arrow of time. Chat reads (context ledger) and commits (DQ4) compete as exposures, and a skeleton replay tests the project-size law. Output per agent comes from the work ledger. In 40 units, joins follow a sublinear kernel ($\alpha\approx0.5$--$0.7$). Activity \emph{after} a join predicts it as well as activity before, so this is co-arrival. Read chat beats commits, and a project's commits grow as $n^{0.70}$ with its agents.}

\hmodel{Model 10 (Potts) in kinetic form, with a preferential-attachment kernel. Agent $i$ joins project $Y$ from the live set $C$. $a_Y$ is other agents' labelled windows on $Y$ in the last 2 active hours, and $s_Y$ their cumulative windows. $h_{iY}=1$ if $i$ held $Y$ before (habit). $\alpha=1$ with $u\propto\log s_Y$ is the Yule--Simon process. The exposures are $M$ (chat mentions of $Y$ read at $i$'s calls in the last 60 min, or after the join: lead), $M^{u}$ (posted but unread) and $C$ (others' commits to $Y$, before or after). Output: $c_{Y}$ is a project's commits in a window with $n_Y$ agents on it, and $\theta<1$ means crowding.}

\hmath{\vspace{-8pt}\begin{gather*}
P(i\to Y)=e^{u_Y}\Big/\textstyle\sum_{Z\in C}e^{u_Z}\\
u_Y=\alpha\log a_Y+\beta_0[a_Y{=}0]+\gamma\log(1{+}s_Y)+\eta\,h_{iY}\\
\text{R2: }u_Y\mathrel{+}=\beta_M\log(1{+}M_Y)+\beta_C\log(1{+}C_Y)\ (+\text{lead, unread})\\
\mathbb E\,c_{Y}\propto n_Y^{\theta},\qquad \mathrm{RR}_{\rm herd}=\text{rate}_{\rm herd}/\text{rate}_{\rm solo}
\end{gather*}\vspace{-10pt}}

\htelos{Herding is co-arrival steered by chat, not stigmergy. Agents pick projects in proportion to others' recent activity, with a sublinear exponent. That activity is as predictive one hour after the join as one hour before, so agents converge in the same hour; they do not follow an accumulated record. Read chat mentions predict joins better than commits, and unread mentions do not. Pile-ons cost little per herded agent (commit rate RR 1.23, n.s.), but they add little to the project: each extra agent adds about 0.7 of a solo agent's commits. Operator rule: expect a project's commits to grow as $n^{0.7}$ with the agents on it. To get parallel output, split work across owned artifacts rather than adding agents to one repo.}

\hbottom{LLM agents pile onto projects in same-hour bursts steered by chat, not by the artifact record, and each extra agent on a shared project adds about 0.7 of a solo agent's commits.}

\hcaveats{Work joins are few (25--101 per period; 51g 321), so per-period work CIs are wide. Whole goal periods are units for \#18--\#44 (exception (d)). The 30-min window is coarser than the 18--50 s read-out delay, so ``before'' and ``after'' share a burst. The read vs unread contrast is not estimable in most units: unread mentions are almost never followed by a join. $\theta$ counts watchers as well as committers. Own units produce 3$\times$ more commits per agent-hour, but that difference follows calendar time. The R3 test is mildly liberal (synthetic size 0.04--0.13). Synthetic validation found and fixed a likelihood bug and two liberal contrasts before the real run (amendment A1).}
