\hwhat{Is a herding wave's size set by how many uncommitted agents read the seeding link within one model-call cycle? We took the first chat link to each project (928 seeds, 23 non-holdout periods). Read-out timing came from the context ledger. We validated on synthetic swarms run on the real call schedules first. \emph{Seeding holds:} adoptions jump $\sim$20-fold at the first link, stay in the poster's room (other-room ratio 0.12), and almost never happen without the link in context (1.5\%). \emph{The clock fails:} prompt readers adopt no more often than later readers ($\mathrm{RR}_{\rm timely}=1.06$ [0.93, 1.22], 726 adoptions). The receptive count adds nothing to held-out wave-size prediction; the project's current share is the only predictor (AUC 0.72 vs 0.46). Poster status adds nothing. The exception is deadline-bound calls: in the \#26 runoff, ballots = readers inside the 100-s window (8 = 8). Holdout not run.}

\hmodel{Models 10 and 03: kinetic Potts with read-out-gated updates. Agent $i$ (state $\sigma_i$: project or none) can switch only at its own model calls. A seed (first chat link to project $X$) is a field pulse felt at $i$'s reading call, at message age $a_i$. $A_X$ is attractiveness, $u_i$ uncommitted, $c_i$ $i$'s call cycle, $g$ a decreasing gate, $k_X$ current adopters. $R$ is the receptive count. Rivals: poster status, a shared field, room size $N$, current share.}

\hmath{\vspace{-5pt}\begin{gather*}
P(\sigma_i\!\to\! X\,|\,a_i)=1-\exp\!\big[-A_X u_i\, g(a_i/c_i)\, e^{\beta J k_X/(N-1)}\big]\\
\mathbb{E}[S]\approx A_X\big[p_{\rm hi}R+p_{\rm lo}(N_{\rm sus}-R)\big],\ \ R=\#\{i: u_i\!=\!1,\,a_i\!\le\! c_i\}\\
\log\mathbb{E}[y_{is}]=\alpha_s+\delta\,\mathbf{1}[a_i\!\le\! c_i]+\gamma u_i+\ldots,\ \ \mathrm{RR}_{\rm timely}=e^{\delta}
\end{gather*}\vspace{-7pt}}

\htelos{Partly useful, mostly as a negative. Operators can stop trying to time project announcements to the agents' call loops: posting when many agents are ``about to read'' buys about 9\%. What does move a pile-on is whether there is a link at all (no link, almost no wave), whether the room already has agents on the project, and whether readers are in the live conversation (3$\times$). For deadline-bound calls such as votes, polls or sign-ups, the clock binds: the wave equals the agents whose next call lands inside the window. In regime III a 2-min window misses about a third of the swarm; $\geq$15 min reaches about 90\%. That is a concrete design rule, although it rests on one election.}

\hbottom{Herding waves are seeded by announcements and bounded by rooms, but their size is set by the project's existing share and the live conversation, not by how many agents read the link within one call cycle; the call clock only binds for deadline-bound calls.}
