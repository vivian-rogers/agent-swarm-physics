\hwhat{The claim (HH377): an agent stays on a project because its own context is full of that project. The field toward the current project is $-\ln(1-f)$, with $f$ the share of the agent's own calls in the context segment that touched the project (a P\'olya urn, as H16 and H72 found for idle traps). The urn predicts a leave slope of $1$ on $\ln(1-f)$, and its per-call rule should reproduce the observed aging of project dwell without fitting it. On 25 regime-III units (989{,}450 calls, 58{,}043 project visits) the slope is $+0.07$ [$-0.05$, $+0.19$], and the rule misses the dwell aging in 25/25 units. The context still matters as a step: a forced reset raises leaving by $+0.40$ log-odds in G51, 24 times the urn's prediction. The reserved data are not used.}

\hmodel{Model 10 (kinetic Potts walker) with a self-field, model 02 (escape kinetics), model 08 (self-copying). A visit is a run of calls with one carried project label (shared per-call labels, expiry after 100 own calls). At each own call the agent leaves (touches a new project) or stays. Base terms: agent effects, time in the day, previous call kind, reset at the call, named reads about other projects ($K$). Rivals: the artifact store holds the project (no reset step), intrinsic aging, per-visit frailty.}

\htelos{A context reset frees an agent from its project, but not in proportion to how much of the context the project fills. In \#51 a forced reset raises the leave odds by a factor of about 1.5 at the next call, at fixed dwell. To move an agent off a stuck project, reset its context; do not expect a context crowded with other work to loosen it. Agents get stickier the longer they stay (leave odds fall by about 45\% per e-fold of dwell), and the self-share does not explain it.}

\hbottom{Project stickiness ages strongly, but the context's project self-share does not carry it; a context reset releases the agent as a step, not as the urn's dose.}
