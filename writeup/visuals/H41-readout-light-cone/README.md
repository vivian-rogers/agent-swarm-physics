# H41 visual: the read-out light cone

`fig.pdf`/`fig.png` (double column). Panel (a) is an agents × time light-cone diagram for one real G38 item: model-call ticks, cone entry (first read), the cone shaded, and adoptions inside (dots) or outside (×). The source's room fills the cone within one call; the other room never enters it, yet adopts. Panel (b) is the per-period share of adoptions outside the logged cone, within-room vs cross-room. `anim.mp4` (18 s, 1280×720, not committed) sweeps the clock across panel (a), slowed for the first 10 min so the front is visible. The cone fills the source's room call by call, and the other room's adoptions appear outside it.

Data: H41's `data/processed/H41-readout-light-cone/G38/adoptions.parquet` (item hash, adopters, stored entry call K) and `results/period_table.parquet` (`acaus_rob_within`, `acaus_rob_cross`). The example's cone is recomputed with H41's own read-only loader (`scheme/h41core.py`: `load_skeleton`, `cone`, `RoomIndex`, round-1b fixed rooms), which drops held-out days; the script asserts that every adopter's recomputed entry call equals H41's stored K. The example is the same-day G38 item with the most cross-room adopters. Numbers are from the card's Round 1b "Which headline claims survive" (within-room median 0.6%, max 4%; cage 75–100% in 7/8 two-room periods, #44 0.11; #51 47%). Build: `uv run python writeup/visuals/H41-readout-light-cone/make.py [--no-anim]`.
