# H94 visual: max-ent work allocation

`make.py` builds `fig.pdf`/`fig.png` (double column, static only; no animation, the claim is a static allocation). Heatmaps (a–f) refit the max-ent hierarchy with the card's own estimator (`hypotheses/H94-maxent-work-allocation/analysis/h94lib.py`, imported unmodified) on `data/processed/H94-maxent-work-allocation/G41/quanta.parquet` (unit 41) and `G51/quanta.parquet` (unit 51d), and assert that D_1 and λ_own match `results/G41.json` and `results/G51.json`. Rows are agents by activity; columns are repos grouped by owner, so ownership reads as a diagonal; colour is the share of quanta on a square-root scale. Panels (g, h) read every testable unit from `results/G*.json` (`lam_own`, `lam_own_lo/hi`, `own_share`, `room_share`, `resid_share_persist`); negative residuals are drawn as 0 (inside the floor). Caption numbers come from the card's Status, Results and Claim that stands (median 2.2 vs 7.8 nats, p = 0.0007; residual ≤ 0.13 in 23/24, #36c 0.23; #40 12.9). Note: for #42a the bootstrap interval [13.3, 16.1] does not contain the point estimate 17.5 (quasi-separation near the cap); the bar is drawn from the interval to the point. Non-holdout only (asserted with `holdout_mask`); repo names are hashes, no text.
