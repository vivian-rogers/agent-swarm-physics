# H50 visual: field vs coupling, measured as transfer lags

`fig.pdf`/`fig.png` (double column). Panel (a) is a labelled simulation: a common input (field, orange) moves every agent at its next call, while a coupling (blue) moves agents hop by hop, one read-out call per hop. Panel (b) shows G38's measured lags: day-start onsets relative to the day median (field) and peer message to receiving call (coupling), on a symmetric log axis. Panel (c) shows the pooled call-cycle kernel of the talk coupling by regime, with the shifted-time placebo as the gray band. `writeup/animations/H50-field-vs-coupling-transfer-lag.mp4` (18 s, 1280×720, not committed) plays the two-panel simulation side by side: field (simultaneous) vs coupling (hop by hop). It burns in the village numbers.

Data: `data/processed/H50-field-vs-coupling-transfer-lag/` (`units/38*.npz` for the lags, recomputed exactly as H50's `readout_delay`; `unit_table.parquet` and `G*/<unit>.json` for the kernels, IVW-pooled as in H50's `figs_summary.py`, plus each unit's placebo jump `gate_k1.talk.J_pl`). Unit days are checked against the holdout. Card numbers (Results, NE/G38 native, Outcome vs prediction): onset IQR 9 s in #38, 82% start before any peer message, read-out median 24 s (regime III), J₁ > 0 in 45/71 units with none negative, regime-III kernel drop at hop 2 then plateau. The pooled 12 s IQR and the 17 s G38 median are this script's pooled values and are labelled that way. Build: `uv run python writeup/visuals/H50-field-vs-coupling-transfer-lag/make.py [--no-anim]`.
